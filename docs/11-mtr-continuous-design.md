# 路径诊断：持续观察（MTR）

2026-10-30。本次在路径诊断内增加“快速查看 / 持续观察”模式，默认快速查看；不增加第五个 TAB。目标是持续记录到最终目标的逐跳 ICMP 回复，用于分析偶发异常，不能单向判定责任设备。

## 首版引擎与采样预算

复用 macOS 系统 traceroute 和 ping，不下载特权程序，不要求 GUI 提权。每轮运行 `traceroute -I -n -m 30 -q 1 -w 1 -z 100 <target>`，不同 TTL 探针始终发往最终目标，不逐个 Ping 路由器 IP。首轮由 traceroute 解析 IPv4，此后将该地址固定在本会话；换地址需新建会话，避免域名轮转混合。取得 IP 后独立运行每次一包的系统 ping，约每秒取目标样本，同时最多一个 traceroute 和一个 ping。

每轮起点至少相隔 5 秒，轮次最长 35 秒。静默路径可能使一轮接近时间预算，因此这不是每跳每秒更新的原生 mtr 引擎，不保证相同 TTL 的严格采样周期；所有记录使用实际观察时间。进程错误、未回复、轮次超时和用户取消分别记录。取消中的未完成探针不补成丢包；休眠/调度空档不补发历史探针。

## 界面与统计

- 模式选择、本工作区目标及开始/暂停/继续；继续同一会话，新建测试才创建新日志。暂停保留历史，继续新建路径段，避免跨暂停拼接。
- 共用 60 秒 / 5 分钟统计窗、路径段选择、历史时间滑块、暂停跟随。目标和跳表使用同一时间范围，但不同采样频率清楚标注。
- 跳表显示 TTL、节点/归属/网关、回复率、无回复率、平均 RTT、P95、近期样本趋势、状态。无回复率按该 TTL 的实际 timeout / (reply + timeout)，取消/错误不计分母。无回复不能归因到最后一次回复 IP。RTT 保留 ms，不除二，不用相邻行差表示链路时延。
- 默认目标 RTT 与五秒 Ping 丢包率时间图；点击一跳增加该跳与目标的 RTT 对照。用散点保留缺失位置，不跨暂停/路径段连线，不给每一行堆完整图。P95 用有限样本的 nearest-rank，显示样本数；不足样本不夸大统计意义。
- 中间未回复用灰色，部分回复/不可达注释用橙色。仅目标有效样本至少 5 个且出现未回复，或目标明确异常时标红；颜色代表当前 ICMP 观察，不等价于业务故障。只给核查提示，不自动判定故障起点。

## 路径分段

同一 TTL 观察到与已知地址不同的有效回复时开启新段，每轮至多一次；提示可能是路径变化或负载均衡。单纯 timeout 不改变地址基线。新段从观察到变化的时刻开始，不回改已保存样本；该轮较早 TTL 的样本仍在旧段，新段需等待后续轮次补齐。每段内不混合其他段的 RTT/比例，历史保留旧段。不是对真实拓扑变化的确定识别。暂停/继续也分段；检测到长调度空档时暂停并丢弃在途结果，继续后新建段。

## 日志与回放

独立目录 `~/Library/Logs/NetPulse/mtr-<UUID>/`：`mtr.csv` 为追加式规范日志，`mtr-diagnostics.txt` 保存有时间戳和轮次的系统原始输出。CSV 首部记录 Type / Version / Session / Target / Started-At / Protocol / Method / 时间和 TTL 预算；状态、实际 IP、最新网关/接口等动态元信息以 `# Key: Value` 追加，读取取最后一个值。数据列：

`id,timestamp,segment,round,kind,ttl,reply_ip,rtt_ms,outcome,annotation,country,province,geo_source`

kind 为 hop / target / event；outcome 为 reply / timeout / error 或事件名称。事件保留轮次完成/超时、分段、暂停/继续。缺失留空，不补零；以 `#` 开头的行均为元信息，可用 pandas `comment="#"` 加工。已知地域随样本快照写入，未解析的保持未知，离线回放不联网重新查询。文件实时追加并同步，写入失败停止探测。

导入目录或 mtr.csv；严格校验类型/版本、会话、数值、唯一 ID、状态与采样行，不把坏数据解释为 timeout。导出只复制配套 CSV/诊断文件。内存保留最近两小时、最多 60,000 条记录，磁盘日志不自动删除；导入最大 50 MB / 250,000 行，展示最后两小时并说明。running/pausing 的历史标为未正常收尾，不恢复发包。日志含目标与路径 IP。
