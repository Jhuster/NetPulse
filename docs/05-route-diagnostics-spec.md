# 路径诊断：需求、交互与实现设计

2026-10-29。依据本轮已确认的 TAB、表格优先、网关/地域/状态标注及按需时序对照设计。本文区分完整设计和本次实现增量，不将后续能力显示成可用功能。

## 1. 用户目标

在质量监测发现异常后，查看到同一目标的可观测路径、逐跳回复与往返时延；能够理解中间不回复的边界，保存结果并交给他人分析。长期目标是持续观察及历史对照，不能承诺由单向探测确定故障设备或责任网络。

## 2. 首页与独立工作区

顶部为 NetPulse 与工作区状态，下面是“质量监测 / 路径诊断”两个大尺寸导航按钮。目标输入和日志操作位于对应 TAB 内，两个工作区可以对不同 IP 同时测试。

```text
NetPulse                         各工作区独立运行
[ 质量监测 · 状态 ] [ 路径诊断 · 状态 ]
当前 TAB 的目标地址 / 更换目标
当前 TAB 的导入、新建测试、开始/停止
当前 TAB 的结果与导出
```

- 各 TAB 独立保存目标、会话、结果与日志。切换不启动或停止采集。
- 更换目标、新建测试和导入只影响当前工作区，保留原日志；不停止或清空另一个工作区。
- 质量监测提供“对该目标做路径诊断”，只复制目标并切页，不自动发包。路径页有测试、结果或另一个已输入目标时必须确认，取消时不改动原结果；确认后只结束路径测试，质量监测继续。
- 日志只能导入到对应工作区；类型不匹配明确提示，不自动改动另一个工作区。
- X 与 Cmd+Q 仍统一停止所有任务、保存并退出。
- 下一版“本地网络”独立选择接口，不需要远端 IP；实现前不展示入口。工作区控制不能以“所有 TAB 都有目标”作为架构前提。

## 3. 路径诊断工作区

表格优先，各自提供目标、模式与开始/停止。模式为快速查看路径（Traceroute）和持续观察（MTR）。未实现的模式明确禁用并说明，不能周期性 Ping 已发现 IP 冒充 MTR。

### 3.1 快速查看路径（本次增量）

- 一次系统 traceroute 扫描，IPv4、ICMP、最多 30 TTL、每 TTL 三个样本、每探针等待一秒，总预算 60 秒。
- 逐行展示进度，不等整个进程完成才显示结果。进度显示实际已观察跳数，不以最大 TTL 伪装已知总进度。
- 总结观察到的目标地址回复、停止原因、实际目标 IP、出口接口/网关、开始时间与协议。
- 跳表按 TTL 排序：节点/网关标签、国家/省份、回复数/已观察样本数、平均 RTT、状态。
- 同 TTL 多个地址保留并展开，不只留下最后一个，也不把它们串成确定的拓扑。
- 点击一行显示该跳的三个 RTT 样本和原始行。标题明确“单次扫描样本”，不画成持续时序。
- 重测生成独立路径日志，保留上次文件；停止保留部分结果；全静默也能终止，不无限等待。

### 3.2 持续观察（早期设计，当前实现见第 12 节）

采样仍向最终目标发送不同 TTL 的探针。所有跳数据持续记录，跳表使用相同时间区间统一刷新；默认展示目标时序，点击行显示该跳与目标对照，可固定少量节点。历史时间选择同时改变摘要、跳表、路径分段和曲线，后台采集继续。

默认候选观察两分钟，近期统计一分钟；实际发包/并发预算按引擎验证调整。不同地址、目标解析或协议变更分段，不能混为同一节点历史。新增引擎前验证权限、事件接口、取消、打包与回放，不让 UI 以管理员身份运行。

## 4. 地域、网关与状态

网关来自对实际目标 IP 的本地路由查询，与回复 IP 匹配后加标签，不直接假定第一跳就是网关。接口为 VPN/隧道或路由没有可用网关时说明实际结果；保留路由查询失败状态。

国家/省份使用可追溯的数据来源。已支持一次安装本地 MMDB，扫描时自动离线查询；无数据库或无匹配时显示未知，私网/共享/保留地址显示不适用。用户导入的 IP 归属 CSV（`ip,country,province`）按精确 IP 匹配并优先覆盖数据库。界面和日志保留来源与数据库构建日期，路径 CSV 保存当时的地域快照，回放不重新查询。安装与格式边界见 [IP 地理归属方案](06-ip-geolocation-options.md)。

状态采用颜色和文字：

| 颜色 | 含义 | 快速扫描使用边界 |
| --- | --- | --- |
| 绿色 | 收到回复 | 不代表已证明业务或长期网络正常 |
| 红色 | 明确探测异常 | 如系统输出不可达标记；说明是观测结果，不定位责任 |
| 橙色 | 需关注/证据不足 | 部分回复、多地址、目标未确认、时间预算耗尽 |
| 灰色 | 未知/未回复 | 中间静默且后续可回复时不能标成转发丢包 |

快速扫描用回复 2/3，不把三样本推断为长期丢包率。无回复时 RTT 留空。MTR 后续可以按同时间段目标异常与后续共同异常形成核查线索，但不能仅凭中间未响应比标红。RTT 不除以二、不以相邻 RTT 差当链路单向时延。

## 5. 状态与错误

空闲 → 运行 → 完成 / 未确认到达 / 用户停止 / 超时 / 失败。回放单独标注离线。进程启动失败、权限不足、DNS 错误、取消与探测未回复分别说明。结束条件依据系统 traceroute 输出及进程结果，结果文案使用“观察到目标地址回复”，不泛化为业务可用。

系统输出限制总大小；目标严格校验并作为独立参数传入；禁止 shell 拼接。域名解析后的目标 IP 从 traceroute 头部记录，网关查询使用该实际 IP。取消及总超时先结束进程，再有限等待/必要时终止，过期回调不能写入新会话。

## 6. 模块与日志

- `RouteModels`：扫描头、TTL 行、逐样本结果、状态与 CSV 编解码。
- `RouteStore`：系统进程、增量输出、超时/取消、本地路由信息、归属导入与日志。
- `RouteView`：路径工作区、逐跳表格、选中样本与原始输出。
- `RootView`：TAB、当前工作区新建确认与目标传递确认；`Workspaces`：按工作区协调新建、导入和目标传递；`TargetInput`：每项测试独立绑定的输入组件。
- `AppLifecycle`：统一退出两个采集器。

每次路径扫描独立创建 `~/Library/Logs/NetPulse/<route-session-id>/route.csv` 和 `route-diagnostics.txt`。CSV 头标明类型/版本、目标、实际 IP、协议、开始时间、结束状态、网关与接口。数据行保存 TTL、样本序号、回复 IP、RTT、结果、ICMP 注释、国家/省份和地域来源。原始输出仅放诊断文本。路径日志与现有 Ping CSV 分开，不改变已有格式。

导出会话目录；导入单个路径 CSV 或目录恢复表格/逐样本图/地域，不发起网络操作。校验文件大小、类型/版本、列名、数值、重复样本；坏行报告，不能默默补造。保存失败停止扫描并明确提示。

## 7. 本次验收

1. 文档在编码前落盘；现有质量监测功能保持可用。
2. 两个 TAB、各自目标锁定和独立控制；切页不停止采集。
3. 真实 .app 启动 traceroute 并逐行显示；本机回环实测，外网受策略限制时如实显示部分/未知结果。
4. 解析单地址、多地址、超时星号、不可达标记和截断行的夹具测试；网关查询匹配与地理未知状态不造假。
5. 路径 CSV 往返一致、损坏输入拒绝/报告、导入不联网；本地归属 CSV 可用于展示。
6. 取消、超时、新会话和退出清理有测试；测试工具进程不影响其他应用进程。
7. 构建新 .app 并实际检查界面。持续 MTR 与在线地理服务不在本次完成声明内。

## 8. 后续验收

MTR 逐探针引擎和统计窗、历史路径分段、对照时序、可固定节点、较长时间运行、真实多路径与目标不回应但端口可用等故障场景。Windows/Android/iOS 各自验证平台能力后适配，不以当前桌面实现推定支持。

## 9. 第一阶段交付与验证记录

本次已实现首页 TAB、各自目标与会话锁定、独立 Ping/路径控制、真实 ICMP 快速扫描、网关/接口查询、逐跳多地址与颜色状态、单次样本图、本地归属 CSV、路径日志导出及离线导入。示例见 [合成回放日志](examples/route-demo.csv)（非实测与真实归属）。

验证结果：

- `./scripts/build.sh` 成功生成本机架构的 `release/NetPulse.app`，本地 ad-hoc 签名。
- `./scripts/test.sh` 通过原有 Ping/CSV/会话测试及新增路径解析、多地址、静默/不可达、真实 ICMP 回环、取消、总预算、本地归属与不完整日志回放测试。
- 真实应用通过本机回环（三个回复）、切 TAB 后后台 Ping 继续、按工作区新建测试与导入，以及两项采集运行时关闭窗口退出的检查。
- 本机对 `1.1.1.1` 的一次公网 ICMP 扫描观察到 17 个 TTL 和目标回复，网关匹配成功，中间静默行未标为转发故障。该短时结果不代表其他网络或目标的成功率。
- 本地归属表测试与离线演示能显示国家/省份；没有联网查询地理信息。真实地址未匹配时仍显示未知。

第一阶段交付时尚未实现持续 MTR、逐跳连续时序和路径分段；2026-10-30 的持续观察增量见第 12 节。长时间耐久、跨平台及多种真实网络环境仍未完成验收。

## 10. 首页可发现性调整

目标区域增加“目标地址”固定标签、提示文字、独立浅色底与输入框蓝色边框；输入字体放大到 20 pt，聚焦时加强边框。会话锁定时显示清晰可复制的目标文字，不再使用变淡的禁用输入框；提供就地“更换目标”入口，仍经新会话确认，保留原日志。

工作区导航改为两枚横向展开、高度至少 70 pt 的按钮：图标 + 17 pt 加粗标题 + 功能副标题 + 当前选择勾选。选中使用深蓝底白字，未选中有边框；颜色之外也有文字与图标提示，保留无障碍选中状态。采集逻辑、日志格式与切换行为不变。

## 11. 独立工作区修订（取代共享目标设计）

每个 TAB 拥有自己的输入和操作区，导航保留大尺寸蓝色选中态。目标字段使用原有高对比度设计，但绑定各自 Store。新建测试的确认文案明确只影响当前项；菜单 Cmd+N 同样作用于当前 TAB。增加工作区隔离测试，覆盖不同目标并发、单项重置、单项导入和受保护的目标传递。

独立工作区验证：`./scripts/test.sh` 已通过不同目标并行、单项重置/导入、目标传递拒绝与确认、不自动扫描等测试。独立 UI 实例已验证不同输入值保持、替换确认可取消，以及新建质量监测后路径目标仍保留。


## 12. 持续观察增量（2026-10-30）

“持续观察（MTR）”已实现，取代上文“后续/未实现”的状态描述。默认快速查看不变；MTR 采用面向最终目标的系统 ICMP TTL 轮询，加独立目标 Ping，不将已发现路由器直接 Ping 作为逐跳探测。表格优先、统一统计窗、目标/节点对照、地址变化与暂停分段、可读 CSV 追加日志和离线回放的具体方法及限制见 [持续观察设计与验证](11-mtr-continuous-design.md)。当前首页为四个工作区，上文两 TAB 为历史阶段设计。
