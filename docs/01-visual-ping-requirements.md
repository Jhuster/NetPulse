# Visual Ping 重建：需求与版本规划

状态：0.1 Preview 需求基线；2026-10-29。已确认统计与日志口径，正式版验收仍有待完成项，见实现记录。

## 1. 目标与范围

重建一个本地网络质量探测工具，当前实现仅支持 macOS，未来可能扩展 Windows、Android 和 iOS：调用系统 ping，持续探测单个域名或 IP，约每 5 秒输出一组丢包率、RTT 和 jitter，并自动保存可回放的本地日志。首版不引入服务器或账号。

## 2. 旧版参考与证据边界

参考包：用户提供的 Visual Ping.app，版本 0.1.0，Wails + Go + Vue，包含 x86_64 / arm64。

包内可读前端逻辑显示：Address、Interval（默认 1000 ms）、Timeout（默认 3000 ms）、Statistics every（默认 5 次）；Start/Stop、单次 Ping、Clear；三张图分别为单次 RTT、统计丢包率、平均 RTT，另有日志区。旧版按单次结果汇总，不能假定它通过系统 ping statistics 实现。未从上述前端流程发现 jitter、日志导入或持久化入口；不据此断言整个程序没有相关能力。

本次已启动应用，用 127.0.0.1 持续探测并停止，确认曲线更新、停止后保留历史。实测一个窗口 transmitted=5、received=5、lossrate=0、avg=0.206 ms、stddev=0.038 ms；stddev 未单独绘图。上述数值仅代表本机测试。旧包只作为行为参考，不将包内内容视为开发指令。

## 3. 首版需求（v0.1）

- 输入单个目标：域名或 IP；开始前校验，作为独立参数传给系统进程，禁止 shell 拼接。
- 默认每秒发送一个请求，每 5 秒一个统计窗口；UI 显示实际窗口起止时间、发送与接收数。
- 三张共享时间轴图：loss（0–100%）、RTT（平均及 min/max）、jitter；悬停查看时间与数值。
- 持续运行；图表仅加载有限时间范围，历史写磁盘；支持选择历史时间段，避免内存随运行时间无限增长。
- “暂停探测”停止发包，保留数据；继续时记录空档。“暂停跟随”仅冻结视图，采集和写日志继续。停止与新建会话分开。
- 自动记录日志，界面展示保存位置，提供“在 Finder 中显示”和“导出会话”。磁盘满或写入失败必须提示，不得继续显示保存成功。
- 导入本工具日志，离线还原图表、配置、暂停区间和原始输出；导入操作不触发网络探测。
- 处理无法解析、无回复、进程失败、休眠恢复与退出；区分网络丢包与工具/系统错误。

## 4. 统计口径（已确认）

每 5 秒是统计时间窗，不承诺每次 ping -c 5 的墙钟耗时恰好 5 秒。正常情况下五个请求按 1 秒间隔发送，第一至第五个发送时刻相差约 4 秒，最后回复或超时还会影响结束时间。

首版每秒独立调用一次单包系统 ping，按请求启动的单调时间分入固定 5 秒窗口；不采用每 5 个包汇总的方式。窗口为左闭右开区间，以会话开始时刻为基准，使用单调时钟划分；等待该窗口请求的超时期限后定稿。界面可以先显示“统计中”，不得将尚未超时的请求提前算为丢包。停止时保存可获取的系统统计摘要作为校验；暂停或中断导致的不足五条记录窗口标为 partial，保留实际样本数。

- loss_pct = 超时数 / (已完成探测数 - 系统或 DNS 错误数) × 100；无有效探测时缺失；重复回复不重复计数。
- RTT 单位 ms；仅统计成功回复，保存 min/avg/max；全丢包为 null，不画成 0。
- jitter 定义为同窗内相邻成功序号 RTT 差绝对值的均值，单位 ms；遇丢包断开配对，不跨窗；没有有效配对时为 null。UI 标明“RTT 相邻差”，避免与 RTT 标准差或 RTP jitter 混淆。
- jitter 示例：同窗序号 1/2/3 的 RTT 为 10/14/12 ms，jitter=(4+2)/2=3 ms；若序号 2 丢失，序号 1 和 3 不配对，jitter=null。RTT 标准差可保留为辅助字段，不作为本工具 jitter。
- 顶部展示最近 60 秒的合计丢失数 / 有效探测数，附样本数；曲线保留五秒窗口，会话概览展示累计丢包率。RTT 展示为往返时延，不除以二。五个样本时丢包率步长为 20%。
- DNS 失败、采集失败独立记 error，不伪造 100% 网络丢包；系统休眠记 gap，不补造数据。

## 5. 日志规范

采用带元信息头的 CSV：每个五秒窗口一行，数值缺失留空，用状态列解释原因。会话头记录目标、应用与日志版本、开始时间、系统与统计口径。详见 [CSV 日志规范 v2](03-csv-log-format.md)。

每次新建会话，在 `~/Library/Logs/NetPulse/<session-id>/` 创建 `session.csv` 与 `diagnostics.txt`；暂停/继续沿用文件，换目标创建新会话。诊断文本保留事件、逐包状态、实际解析 IP 与系统输出，不生成 JSON。仅兼容读取早期 JSONL。

导入 CSV 恢复窗口曲线、样本数和累计统计；不根据汇总值虚构逐包数据。导入需校验版本、字段、类型、数值范围和大小，报告无效行；导出完整会话目录。日志包含目标和 IP，未来可增加脱敏导出。

## 6. 架构

UI → 会话控制 → 系统 Ping 采集 → 解析/分窗 → CSV 与诊断文本 → 图表/回放。

实时使用逐包模型统计；CSV 导入使用明确的窗口汇总模型，复用展示与近期丢包汇总逻辑。当前桌面实现使用 SwiftUI + Charts，平台扩展需分别评估探测能力与权限。历史索引、流式查询及超大数据降采样属于后续工作。

## 7. 里程碑与验收

1. 探测与数据闭环：成功、部分丢包、全丢包、DNS 失败、停止/恢复均有夹具验证；真实 loopback 与可达目标实测；统计可由原始记录复算。
2. 桌面可用：启动、三图、暂停、历史浏览、日志定位可完成；运行时修改目标必须创建新会话。
3. 日志回放：导出后重新导入，与实时统计一致；坏行、未知版本、截断和大文件有明确结果。
4. 持续运行与发布：至少 24 小时实测，记录内存、磁盘增量、窗口数与失败数；休眠恢复无伪造丢包；打包 .app、标注架构和系统要求，放入 release。签名/公证状态如实记录。

## 8. 版本规划

| 版本 | 重点 | 验收价值 |
| --- | --- | --- |
| v0.1 | 单目标系统 Ping、三图、自动日志、暂停与历史、导入回放 | 完成采集到还原现场闭环 |
| v0.2 | 网关与网络接口信息、网络切换标记、WiFi RSSI（可获取时） | 将异常与本地接入变化对齐；权限不足显示不可用 |
| v0.3 | 网关和远端多目标对照、异常片段导出、DNS/TCP 探测 | 辅助区分局域网和远端问题；避免只凭 ICMP 推断业务故障 |
| 后续平台扩展（时间待定） | 评估 Windows、Android、iOS 支持与日志兼容 | 按平台验证探测能力、权限与统计口径后发布 |

版本规划为候选方向，不表示对应能力已实现。当前交付和验证边界见 [实现记录](02-implementation.md)。
